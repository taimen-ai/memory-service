# Граф памяти: AGE против таблиц — замер MEM-ADR-023 п.6

Отчёт TASK-001286. Решение — [MEM-ADR-023](../docs/decisions/ADR-023-graph-on-postgres-tables.md),
п.6 «Приёмка по замеру»; протокол операций — `GraphBenchOps` (ADR-016 §10).
Сырые цифры — [`results/graph-engines-2026-10-03.json`](results/graph-engines-2026-10-03.json).

## Итог

- **Приёмка условная, на синтетическом графе:** ни одна операция на таблицах не медленнее
  AGE — ни по p50, ни по p95. MEM-ADR-023 п.6 требует прогона на копии company-brain; копия
  к замеру не выдана, поэтому **контрольный прогон на копии обязателен перед выкаткой**
  (TASK-001293): на восстановленном дампе, после переноса и до переключения образа, командой
  из раздела «Повторить». Если хоть одна операция на таблицах медленнее AGE — выкатка
  останавливается, задача возвращается владельцу с `EXPLAIN (ANALYZE, BUFFERS)`. Ближе всего точечные запросы: `temporal_filter` на таблицах в 4,0 раза быстрее по
  p50, `entity_lookup` — в 4,3 раза. Обходы и гибридный запрос — на два–четыре порядка.
- **Обход ADR-010 (`CB_DB_JIT=false`) для графа больше не нужен.** На таблицах самая дорогая
  оценка плана во всех операциях, включая гибридный запрос, — 8 291 при пороге
  `jit_above_cost` 100 000. JIT не включается ни в одном запросе (в
  `EXPLAIN (ANALYZE)` нет раздела `JIT:`), а разница `jit=on`/`off` в двух прогонах меняет
  знак, то есть это шум. У AGE оценка 713 млн — та самая причина ADR-010.
- **Контрольный прогон на копии staging (2026-10-03) выкатку не остановил** — решение
  владельца, см. «Контрольный прогон на копии staging». В рабочем namespace графа все
  операции на таблицах быстрее AGE по p50 и p95; в `tenant:4796…` p95 гибридного запроса
  на таблицах в первом прогоне хуже (130,9 против 113,5 мс), на повторе — лучше, а
  графовая часть на таблицах < 0,5 мс против ~40 мс у AGE: время — в общем канале
  наблюдений.
- Попутно: гибридный запрос на таблицах (~0,5 с) почти целиком тратится не на граф, а на
  полнотекстовые каналы (см. «Где время гибридного запроса»).

## Что мерили

| Операция | Таблицы (`TableBenchOps`) | AGE (`AgeBenchOps`, код `a4dc7fe`) |
|---|---|---|
| `entity_lookup` | `GraphStore.get_node` | `MATCH (n {natural_key: $nk}) WHERE n.namespace IN $nss` |
| `one_hop`, `two_hop` | `expand_neighbors(hops=1\|2, limit=40)`: фронт массивом по индексам рёбер | `MATCH (a)-[*1..N]-(b) … RETURN DISTINCT` |
| `neighborhood` | 5 ключей, 1 хоп, лимит `CB_CONTEXT_MAX_NODES` (60) | то же запросом AGE |
| `temporal_filter` | `FactStore.facts(subject, as_of)` | `MATCH (a)-[r]->(b) WHERE r.fact_id IS NOT NULL …` |
| гибридный запрос | `build_context`, стратегия hybrid | тот же `build_context`, граф и факты компилятора — AGE |

Гибридный запрос — ровно путь Context Compiler: каналы lexical (чанки и наблюдения),
vector (pgvector, HNSW), graph (обход на `CB_CONTEXT_MAX_DEPTH` = 2 хопа от двух якорей и
топ-3 хитов вектора), facts (temporal-факты якорей), recent, фильтр видимости
`allowed_scopes` (5 scopes из данных) и запись трассы. У AGE на время вызова в компиляторе
подменены `GraphStore`/`FactStore` на варианты с запросами кода до TASK-001284
(`benchmarks/graph_ops.py`, `age_compiler`); остальные каналы общие и идут по тем же
таблицам. Сам компилятор с `a4dc7fe` не менялся.

Выборки детерминированы по seed: 50 ключей (25 хабов из верхних 10 % по степени и 25
обычных узлов со связями, через один), 50 субъектов фактов, `as_of` — медиана
`valid_from` фактов namespace (`2025-03-23T11:33:50Z`), 50 текстов запросов — начала
случайных чанков (namespace без чанков — начала наблюдений, без них — `natural_key` узлов
графа); эмбеддинг запроса — детерминированный fake-эмбеддер размерности
таблицы чанков. Конфигурации идут вперемешку по операциям, у каждой своё соединение,
JIT — `SET jit` сессии. Перед прогоном — `ANALYZE` всей базы.

## Где время гибридного запроса

`EXPLAIN (ANALYZE, BUFFERS)` всех запросов одного вызова на таблицах (`--explain-dir`):

| Запрос | мс |
|---|---:|
| полнотекстовый поиск по чанкам (`ts_rank(to_tsvector(…))`), канал lexical | 104 |
| то же внутри гибридного поиска канала vector | 106 |
| полнотекстовый поиск по наблюдениям | 114 |
| граф: узлы, достигнутые за два хопа (до отбора лимита) | 29 |
| граф: два шага обхода по рёбрам | 9 |
| вектор (HNSW) | 4,7 |
| факты якорей, четыре запроса | < 0,3 |

Граф — около 40 мс из 0,5 с. Полнотекстовые запросы считают `to_tsvector` и `ts_rank` по
строкам — это общая часть обоих движков, к MEM-ADR-023 не относится. Отдельно можно
ускорить и графовый канал: `expand_neighbors` читает все узлы, достигнутые за два хопа, и
режет до лимита уже в Python.

## Повторить

### На любой базе с графом AGE (например, на копии company-brain)

Только на копии: перенос пишет таблицы графа, а замер — таблицу трасс (удаляется в конце).
Сторона AGE ходит через `cypher()`, поэтому после `pg_dump`/`pg_restore` каталог AGE должен
быть исправлен (`cb migrate-graph-from-age` предупреждает о битом каталоге и даёт рецепт).

```bash
export DSN=postgresql://USER:PASSWORD@HOST:PORT/DB      # копия базы, роль-суперпользователь
CB_DATABASE_URL=$DSN CB_GRAPH_NAME=company_brain uv run cb migrate-graph-from-age
psql "$DSN" -c ANALYZE
uv run python benchmarks/bench.py engines --dsn "$DSN" --graph company_brain \
  --out company-brain.json --markdown company-brain.md --explain-dir company-brain-explain
```

По умолчанию: namespace — самый крупный в графе (`--namespace` задаёт явно), таблицы
чанков и наблюдений — `chunks` и `observations` (`--chunks-table`,
`--observations-table`), конфигурации `age:off,tables:off,tables:on,age:on` (`--configs`),
200 вызовов (`--iterations`), бюджет 120 с на операцию и конфигурацию
(`--budget-seconds`), seed 42. Таблица p50/p95 для этого отчёта — файл `--markdown`.

### Синтетический граф этого отчёта

```bash
docker run -d --name bench-pg -e POSTGRES_USER=brain -e POSTGRES_PASSWORD=brain \
  -e POSTGRES_DB=bench -p 127.0.0.1:55486:5432 memory-db      # образ infra/memory-db
export DSN=postgresql://brain:brain@127.0.0.1:55486/bench
uv run python benchmarks/graph_gen.py --dsn "$DSN" --graph bench_graph --seed 42 --nodes 28000
CB_DATABASE_URL=$DSN CB_GRAPH_NAME=bench_graph CB_DEFAULT_NAMESPACE=tenant:bench:ws:main \
  uv run cb migrate-graph-from-age
psql "$DSN" -c ANALYZE
uv run python benchmarks/bench.py engines --dsn "$DSN" --graph bench_graph \
  --chunks-table bench_chunks --observations-table bench_observations \
  --out run.json --markdown run.md --explain-dir explain
```

Генерация и перенос — около полутора минут, замер всех четырёх конфигураций — около
получаса (почти всё время — бюджеты AGE в `two_hop`, `neighborhood` и гибридном запросе).
